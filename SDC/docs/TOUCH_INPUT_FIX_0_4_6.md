# 0.4.6 大厅按钮失效修复

## 用户报告与原因

用户报告刚进入大厅，所有菜单和开始行动按钮都有按下反馈，但松手后仍然变暗、没有动作。
这是共用 TouchButton 的输入所有权故障，普通点击无法发出 `pressed` 信号。

工程开启 `pointing/emulate_mouse_from_touch`，供原生下拉框、滑条等控件使用。
[Godot 4.6 的输入实现](https://github.com/godotengine/godot/blob/4.6-stable/core/input/input.cpp#L780-L826)
会先分发触摸生成的模拟鼠标事件，再分发原始触摸。

此前用“最近 500 毫秒有触摸才忽略模拟鼠标”的做法，与新增的单指所有权保护冲突：

1. 第一次模拟鼠标按下先到，按钮尚无触摸时间记录，错误地用鼠标指针 `-2` 占用按钮并变暗。
2. 原始触摸按下随后到达，被“已有所有者”保护拒绝。
3. 正常短按松手时，模拟鼠标释放落入 500 毫秒过滤窗口，被忽略；原始触摸释放的编号又不是 `-2`。
4. 两条释放路径都无法结束这次按压，按钮一直变暗；后续点击继续被拒绝。

同样的时间判断还出现在仓库、滚动容器和布局编辑画布；后者也有单指所有权保护。

## 修改

- `touch_button.gd`：所有模拟鼠标按下、移动、释放统一按 `device == -1` 忽略，直接处理原始触摸；取消事件不执行动作，应用暂停时清理按压状态。
- `touch_scroll.gd`：使用同一来源判断，不再让触摸的鼠标副本开启第二次手势；首个触点结束前，其他触点不抢占滚动；隐藏、切后台或暂停时清理手势。
- `ui_inventory.gd`：去掉 500 毫秒判断，只处理真实触摸或真实鼠标，第二个触点不能覆盖当前拖放所有者；鼠标取消不执行放置。
- `ui_control_layout_canvas.gd`：相同的来源过滤，避免编辑器拖动被先到的模拟鼠标锁住。

保留原生控件需要的鼠标模拟设置。地图、人物、枪械预览和战局控制原本已经按来源忽略模拟鼠标，沿用现有实现。
按钮仍然在有效松手时执行一次动作，滑动或取消不能激活商品/菜单；不改库存数据和存档格式。
