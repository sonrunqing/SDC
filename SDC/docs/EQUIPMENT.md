# 装备系统与可编辑数据

当前是可玩的系统原型：256 个原创架空装备条目，共用商店、仓库、改枪台和战局数据。24 把枪和 145 个配件各有自己的原创低多边形 GLB 模型，改枪台可以实时查看装卸组合，战局使用同一套拼装逻辑。模型由程序构建，视觉风格仍处于原型阶段。装备和游戏币只用于游戏内经济。

| 内容 | 已配置数量 | 规则 |
| --- | ---: | --- |
| 冲锋枪 / 步枪 / 狙击枪 / 霰弹枪 / 机枪 / 手枪 | 各 4，共 24 | 每把有不同接口组合和参数 |
| 枪械配件 | 145 | 40 枪口、8 握把/支架、16 枪托、46 供弹组件、12 瞄具、8 激光、15 护木 |

## 数量和装配规则

背包和弹挂甲没有 `level` 字段。容量是负重额度，重量是装备自身占用的负重。弹挂甲是躯干防护装备，与防弹衣互斥；四款采用相同 `protection=16`，由容量、重量和价格区分，不存在隐藏防护等级。

每个头盔有一个面罩位置，采用 A 轨或 B 轨之一。整个目录有两种卡槽标准，并非同时安装两个面罩。面罩必须与头盔的 `visor_mount` 匹配；面罩高低等级不限制能否装上。

枪械使用 `slots: {槽名: [接口标准]}`。配件必须同时满足槽位、物理接口和可选的 `weapon_ids` 平台限制。相同口径不代表弹匣、护木或枪托互通。例如芦苇 R9 和雨燕 S9 都用 9×19 mm，但弹匣不同。獾 B556 和鹪鹩 W556 使用真正共享的 AR 供弹标准；两把枪其他接口不同。

部分武器没有前握把、枪托或激光位置。护木配件只修改参数，不会凭空生成额外插槽。消音器、消焰器、补偿器和制退器共占 `muzzle` 槽，不能叠加；同一槽也只能安装一件其他配件。

## 数据和属性

- `data/items.json`：运行时唯一装备来源，结构为 `{schema_version: 1, items: [...]}`。
- `scripts/generate_catalog.py`：维护基础数据的生成器，运行后重建 JSON 和 CSV。
- `scripts/catalog.gd`：装备检索、兼容检查、参数合并及完整性验证；Autoload 名称为 `Catalog`。
- `docs/装备目录.csv`：可用表格软件审阅的中文目录，含所有 ID、价格、接口、限制、参数和独立模型路径。
- `assets/modular/weapons/<weapon_id>.glb`：24 个独立枪体模型。
- `assets/modular/attachments/<attachment_id>.glb`：145 个独立配件模型。
- `data/weapon_geometry.json`：枪械安装点及原厂部件配置，供改枪台和战局共用拼装组件读取。

武器参数为 `damage`（基础整次射击伤害）、`rpm`（每分钟射击数）、`magazine`（装填上限）、`recoil`（越低越稳）、`accuracy`（0–100，越高越准）、`ergonomics`（0–100，越高越灵活）、`range`（世界米）和 `noise`（0–120 相对枪声强度）。霰弹枪的 `damage` 是整次射击合计值。

配件 `modifiers` 均为加法。`Catalog.weapon_stats(weapon_id, installed_by_slot)` 先验证兼容性，再合并并限制合理边界；无效配件不提供加成，原始数据不被修改。扩容弹匣的 `magazine` 为增量，不是绝对容量。例如同一 AR 加长供弹组件 `+10`，在 30 发基础枪上变为 40 发，在 20 发基础枪上变为 30 发。

弹药 `penetration` 与护甲防护比较。伤害使用 `ballistics.bonus_damage` 加在枪械基础伤害上，微量威力系数、初速系数及阻力共同影响近距威力和远距衰减；`damage_multiplier` 仅为兼容旧目录保留，战斗不再使用。枪只能使用同 `caliber` 的弹药。详见 [伤害与经济调参](BALLISTICS_AND_ECONOMY.md)。

`Catalog.get_item(id)` 返回字典；外部应只读使用。未知 ID 返回空字典。`model_path(id)` 返回该物品的 `visual_model` 路径，未知或没有独立模型的物品返回空串，不会替换成另一把枪。`by_kind`、`by_category`、`compatible_attachments` 可供界面查询；`compatible` 和 `visor_compatible` 是装配判断依据，界面不能只按名称猜测兼容。

## 验证

```bash
python3 scripts/generate_catalog.py --require-models
godot --headless --editor --path . --import
godot --headless --path . --script res://tests/test_catalog.gd
```

运行时验证检查重复 ID、必填字段、负数/倒卖价格、数量分布、每把枪独特接口配置、每个槽位有配件、每件配件有可安装武器、专用平台引用、弹药口径覆盖、头盔/防弹衣级别分布和面罩可达性。模型声明必须有 169 个不同路径，路径需匹配物品 ID 和枪体/配件目录。`validate_models(true)` 还检查所有独立模型已导入且可加载为场景。

目录测试额外验证错误螺纹、错误槽位、同口径专用弹匣互斥、通用件共享、A/B 面罩互斥、容量装备无等级、配件实际改参、基础数据不变和独立模型可达性。仅编辑数据、尚未重建模型时可添加 `-- --metadata-only` 暂时跳过资源存在检查；交付验证须运行默认完整检查。

## 模型来源

这 169 个模块化模型是本项目程序构建的原创几何，不复制商业游戏枪械资产。模型名称和装备参数同样使用本项目架空设计。环境中的 Kenney 免费资源继续按其原许可证使用，来源见项目 `THIRD_PARTY_ASSETS.md`。护甲、背包、弹药和战利品的目录数量不计入这 169 个枪体/配件模型。
