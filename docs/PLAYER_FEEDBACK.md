# 玩家反馈与后续设计标准

状态：active。整理于2026-10-18，来源为本对话的用户反馈；不是已完成功能清单。
用户明确要求持续记录每次反馈，并据此判断希望的效果、为以后发展做准备。新增反馈先更新这里和必要决定，再执行；用户后续明确纠正优先，保留被取代关系。

## 已明确的长期要求

### 画面与信息层级

- 手机优先，重做过小、贴边、又矮又胖的菜单布局；大厅和各页面要美观，操作区域要够用。
- **次要信息、详情和次要操作不得长期挤占主画面；点击后在整体图层上方显示窗口。** 物品详情应在物品旁弹出小窗；关闭、未选择时不预留空间。旋转、拆分、出售等上下文操作随物品出现。
- 不要常驻的橙色焦点光、黄橙/青绿自动切换或按钮闲置动效；只保留点击和实际交互反馈。
- 局内菜单是很小的圆形齿轮；搜索/拾取也是圆形，只在靠近可接触物资时显示和响应。
- 大部分移接旧Ashfront的局内画面、镜头、光照和动作；四臂准星结合右下瞄准摇杆，看到人物和枪口当前方向。

### 手机操作与设置

- 删除人类键鼠适配和触摸转鼠标。左侧移动、右下方向瞄准、左上独立开火，三指互不抢占，移动/瞄准不能消耗弹药。
- 整个游戏区分轻点、双击、长按拖动、滑动滚动；商店/其他列表滑动不能误选或激活商品。按钮松手应恢复且执行动作。
- 设置需有自定义按键位置、大小等操作布局，以及帧率、分辨率、图像、音效。
- 地图预览区域控件应紧凑且能看到多个选项；可平移、缩放、旋转；重复开始不能让地图闪没，开始行动必须能真正进入游戏。

### 装备与格子

- 装备与仓库融合：左装备与携行容器，右500格仓库；每个物品有实际占格，容量按弹挂/背包块状格子显示。
- 拖动、选中后点目标格、双击都能快捷放置，并智能横竖旋转，支持多格弹匣。
- 普通弹挂只储物，无防弹，不抢护甲栏，可同穿护甲和背包。防弹弹挂为商店独立组，替代护甲；护甲栏淡色映射同一物品，不可复制物品或重复计重。普通名称统一“弹挂”。
- 所有物品有实际详细资料；单次选择即能看邻近小窗，不缩小仓库；不能破坏继续点放置、双击或拖动。
- 改枪性能为后坐力控制、水平后坐力控制、人机功效、射程、击发威力、射速、精准度；参数增益用+，高值代表更好。

### 物资与美术

- 物资合理放在建筑/容器内，箱子摆放有逻辑。模型需要碰撞、调整比例与位置、模块拼装并改善整体工业区观感。
- 打开容器进入专门搜索页和动画，逐件发现，只拿所需物品；不自动把全部塞进背包，不加“拿取所选”确认按钮，沿用仓库的双击/点放/拖动。
- 变卖物至少48种，模型精致；工业品、收藏品、生活物品、高精度仪器、金属及扩展分类。生活物品多、收藏品多为贵重、精密仪器少且贵重。
- 品质背景灰/绿/蓝/黄/红。旧“淡色→1.6倍→再2倍”反馈后，最新要求是**去灰雾、实色背景与原色物品分层**；未搜索前不显示品质色。
- 混元模型工作流：用户txt每行一个提示词，V3.1、50K、卡通纹理、GLB；保存到D:/aa/模型库，按物品命名，只保留一个.glb后缀，避免重复生成已完成模型。

### AI游玩与交付

- GitHub入口面向具备自己本地/云环境的agent，能拉取并启动游戏；不需要依赖用户电脑公开托管。
- **AI必须看真实游戏画面、走原始触摸/多指流程，快速完整体验。指令成功、状态正常、导出成功不能当作玩家体验通过。** 发布前覆盖大厅、仓库、装备、商店、改枪、地图、战局、搜索拾取和设置，检查压缩、遮挡、滚动、误触等问题并改良。
- 每次交付新版本，固定包名和签名、递增versionCode，正常升级保留数据。旧云端0.3.0到固定签名0.4.3的卸载为一次性例外。
- 最新APK应在本对话提供本地文件入口，GitHub同步当前Latest与首页；代码上传并可供其他AI读取、审查，PR不因审查请求而自动合并。

## 据反馈推断的方向（可被用户后续纠正）

- 更偏向暗区/三角洲式的直接整理与搜刮节奏：核心区域大、上下文功能近手、操作步骤少。
- 信息密度需有层次；“增加功能”不等于把说明、工具栏和详情一直摆满页面。
- 希望代理主动根据已知反馈发现同类问题，并改良后交付，而不是等用户逐处指出。
